## 1. 使用的系统与框架

本项目是微信小程序（miniprogram）+ 微信云开发，没有引入第三方配置库。配置由以下原生机制构成：
- 小程序框架配置文件：`app.json`、`project.config.json`、`sitemap.json`
- 云函数声明文件：`cloudfunctions/api/config.json`
- 应用级 JS 初始化：`app.js`
- 前端集中常量模块：`utils/constants.js`
- 云函数入口路由与权限声明：`cloudfunctions/api/index.js`、`cloudfunctions/api/config.json`

## 2. 关键文件

| 文件 | 作用 |
|---|---|
| `utils/constants.js` | 所有运行时可配置值（envId、云函数名、集合名、分类、模板 ID、限制等）的单一来源 |
| `app.js` | 读取 `ENV_ID` 并调用 `wx.cloud.init({ env: ENV_ID })` 完成云开发初始化 |
| `services/cloud.js` | 通过 `CLOUD_FUNCTION` 常量统一走 `wx.cloud.callFunction`，不直连数据库 |
| `cloudfunctions/api/index.js` | 单云函数 + action 路由表，集中处理鉴权/校验 |
| `cloudfunctions/api/config.json` | 云函数权限（`subscribeMessage.send`）与定时触发器（`dailyReminder`） |
| `app.json` | 页面路由、tabBar、窗口样式、隐私权限声明 |
| `project.config.json` | 开发者工具项目配置（appid、基础库版本、编译选项、打包忽略规则） |

## 3. 架构与约定

### 3.1 前端配置集中在 `utils/constants.js`
该文件顶部注释明确说明「云开发环境与集合名集中在这里，改环境只改一处」。它导出：
- `ENV_ID`：云开发环境 ID
- `CLOUD_FUNCTION`：云函数名称（默认 `api`）
- `COLLECTIONS`：数据库集合名映射（`USERS`、`TRIPS`、`POIS`、`EXPENSES`）
- `MESSAGE_TEMPLATES`：订阅消息模板 ID
- `POI_CATEGORIES` / `EXPENSE_CATEGORIES`：业务枚举
- `LIMITS`、`DURATIONS`、`DEFAULT_START`、`BUFFER_MIN`：行为参数

其他模块通过 `require('../utils/constants')` 使用，而不是各自硬编码。

### 3.2 云开发初始化在 `App.onLaunch` 中完成
`app.js` 从 `constants` 取 `ENV_ID`，调用 `wx.cloud.init({ env: ENV_ID, traceUser: true })`，并把 `ENV_ID` 写入 `globalData.envId`。如果基础库不支持云开发（`!wx.cloud`），直接 `console.error` 并返回。

### 3.3 网络层通过 `services/cloud.js` 统一封装
所有写操作都走云函数，注释写明「前端不直连数据库，这样 V1.5 加成员/权限时只改服务端，不动页面」。
- `call(action, payload)`：构造 `{ action, payload }` 调用 `wx.cloud.callFunction(name: CLOUD_FUNCTION)`
- `run(action, payload, loadingText)`：带 loading、统一 toast、对 `code === 'conflict'` 特殊处理（跳过 toast，交给页面弹选择框）

### 3.4 后端单云函数 + action 路由
`cloudfunctions/api/index.js` 维护一个 `routes` 对象，将字符串 action（如 `trip.list`、`poi.save`）映射到处理器。定时触发器（`event.Type === 'Timer'`）绕过 action 路由，直接调用 `notifyHandler.sendDue()`。

### 3.5 云函数权限与触发器
`cloudfunctions/api/config.json` 声明：
- `openapi.subscribeMessage.send` 权限
- `dailyReminder` 定时器触发器，cron 表达式 `0 0 20 * * * *`（每天 20:00）

### 3.6 小程序框架级配置
`app.json` 注册 12 个页面路径、定义 tabBar（行程/记账/我的）、声明 `requiredPrivateInfos`（`chooseLocation`、`getLocation`）和 `scope.userLocation` 权限描述。
`project.config.json` 固定 appid、基础库 `3.5.5`、关闭 URL 检查、启用 ES6/minifyWXML/minifyWXSS，并在 `packOptions.ignore` 中排除 `docs`、`.backup`、`.qa-tmp`。

## 4. 约定与约束

**观察到的约定：**
- 所有跨模块的配置值（环境 ID、集合名、分类、模板 ID、限制）放在 `utils/constants.js` 一个文件中导出，由 `app.js`、`services/cloud.js` 和各业务 services 共同引用。
- 前端不直接调用数据库 API，所有写操作统一通过 `services/cloud.js` → `wx.cloud.callFunction('api', { action, payload })`。
- 云函数只有一个入口 `index.js`，新增接口只需在 `routes` 表添加一行，无需部署新云函数。
- 云函数权限与定时任务在 `cloudfunctions/api/config.json` 集中声明。
- 小程序页面路由、tabBar、隐私权限在 `app.json` 集中声明。
- 开发者工具相关设置（基础库版本、编译开关、打包忽略）在 `project.config.json` 中集中管理。

**有文档化或代码强制的规则：**
- 「云开发环境与集合名集中在这里，改环境只改一处」——`utils/constants.js` 顶部注释。
- 「所有写操作都走云函数：前端不直连数据库，这样 V1.5 加成员/权限时只改服务端，不动页面」——`services/cloud.js` 注释。
- 云函数对未知 action 返回 `{ ok: false, message: '未知操作：' + action }` ——`cloudfunctions/api/index.js` 第 58-60 行，属于运行时校验。
- 定时触发器走独立分支，不经过 action 路由 ——`cloudfunctions/api/index.js` 第 44-54 行。
- 客户端对 `err.code === 'conflict'` 不做 toast，交由页面自行处理 ——`services/cloud.js` 第 42-44 行。
- 云开发初始化失败（基础库不支持）时直接 `console.error` 并 return，不再继续 ——`app.js` 第 11-14 行。

**未发现的机制：**
- 没有 `.env`、`.yaml`、`.toml`、`application.properties` 等外部配置文件。
- 没有 feature flag、A/B 测试、远程配置中心。
- 没有多环境（dev/staging/prod）切换逻辑；`ENV_ID` 是硬编码常量。
- 没有 secrets 管理；敏感值（如 `ENV_ID`、模板 ID）以明文常量形式存在。
