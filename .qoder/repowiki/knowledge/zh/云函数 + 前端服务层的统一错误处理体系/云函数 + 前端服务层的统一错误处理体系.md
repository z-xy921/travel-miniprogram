## 2. 关键文件与职责
- `cloudfunctions/api/index.js`：唯一云函数入口，维护 `routes` action→handler 映射；对定时触发器与普通请求分别 try/catch，统一返回 `{ ok, data, code, message }` 结构。
- `services/cloud.js`：前端唯一云函数调用入口。`call` 把云函数响应包装为 Promise，成功时 resolve `result.data`，失败时构造 `new Error(result.message || '服务暂时不可用')` 并挂上 `err.code = result.code`；`fail` 回调直接 reject 网络异常。`run` 是带 loading 的便捷方法，统一 hideLoading + toast，但对 `err.code === 'conflict'` 跳过 toast（因为需要弹选择框让用户决定）。页面侧只写成功分支，异常由 `run` 吞掉 UI 表现后重新 throw。
- `cloudfunctions/api/guard.js`：权限与并发控制工具，集中抛错点：`requireOwner`、`assertVersion`、`bumpVersion`、`getTripForMember` 等；提供工厂函数 `conflictError()` 创建带有 `code='conflict'` 的 Error，用于乐观锁冲突场景。
- 各业务 handler（`expense.js`、`photo.js`、`poi.js`、`trip.js`、`notify.js`、`db.js`）：在参数校验、资源不存在、权限不足、配额超限等场景直接 `throw new Error('...')`，不自行 catch。

## 3. 架构与约定
### 3.1 错误传播路径
```
业务 handler 抛 Error → index.js 顶层 catch → 返回 { ok:false, code, message }
→ services/cloud.js call() 转成 JS Error(code/message)
→ run() 统一 toast（非 conflict）→ 继续向页面层抛出
→ 页面层可 catch 特定 err.code 做差异化处理（如 conflict 弹确认框）
```
### 3.2 错误对象约定
- 普通错误：`new Error('人类可读消息')`，无额外字段。
- 业务语义错误：附加 `err.code` 字符串，当前已使用的值只有 `'conflict'`（版本冲突），用于让前端区分“刷新重试”和“普通失败”。
- 云函数返回体约定：成功 `{ ok: true, data }`；失败 `{ ok: false, code: '', message: '' }`。`index.js` 注释明确说明 `code 只用于客户端分派`，`message` 才是用户可见文案。
### 3.3 定时任务与常规请求分离
`index.js` 对 `event.Type === 'Timer'` 或 `TriggerName` 走独立分支，单独 try/catch 并记录 `[api] timer` 日志，避免定时任务异常污染正常 API 的错误码。
### 3.4 乐观锁冲突处理
`guard.js` 通过 `assertVersion`（读端检查版本号）+ `bumpVersion`（写端原子更新 version）实现并发保护；任一环节失败都 `throw conflictError()`，前端收到 `err.code==='conflict'` 后弹出选择框而非简单 toast。

## 4. 观察到的约定与约束
- **服务端不暴露堆栈**：所有 `catch (err)` 仅取 `err.message` 和 `err.code` 返回给前端，原始堆栈只留在 `console.error('[api]', ...)` 日志中。
- **前端不直连数据库**：`services/cloud.js` 顶部注释写明“所有写操作都走云函数”，前端只通过 `call`/`run` 调用，错误来源单一可控。
- **UI 错误展示集中在 `run`**：页面级 handler 无需自己 `wx.showToast`，`run` 自动处理 loading 与 toast；仅在 `err.code === 'conflict'` 时跳过 toast，交由调用方自行弹窗。
- **业务校验一律抛错**：各 handler 的参数缺失、权限不足、配额超限、资源不存在等均以 `throw new Error(...)` 表达，不在 handler 内部 return 错误对象。
- **错误码枚举未集中定义**：目前仅使用 `conflict` 一个 code 值，散落在 `guard.js` 的 `conflictError()` 中，没有统一的 error-code 常量表。
- **无 panic/recover**：Node.js 环境不使用 `process.on('uncaughtException')` 等全局恢复机制，依赖微信云函数平台自身的进程重启能力。
